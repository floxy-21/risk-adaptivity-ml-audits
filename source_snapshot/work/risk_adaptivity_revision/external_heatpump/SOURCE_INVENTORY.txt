Documented software semantics:
https://github.com/openenergymonitor/heatpumpmonitor.org/blob/main/www/Modules/timeseries/timeseries_controller.php
The /timeseries/data controller forwards start/end, interval, average, delta, timeformat, skipmissing=0 to the configured Emoncms backend. The public response maps feed IDs to named feeds. /available strips backend server, API key and feed IDs. Those private backend details should not be sought or inferred. Average=0 and delta=0 request cumulative samples rather than averages/differences, but do not establish that historic stored values were never repaired.

Backend format context (conditional; native engine not exposed for these IDs):
https://docs.openenergymonitor.org/emoncms/developer/timeseries/Fixed-interval.html
PHPFina uses float32 values and floors write timestamps to its interval; missing values can be NaN or optionally joined linearly. Apply these properties only if the relevant backend is established, not as a universal description of all selected feeds.

Cumulative-feed provenance warning:
https://github.com/openenergymonitor/HeatpumpMonitor/blob/master/HeatpumpMonitorTH/installation.md
The naming convention identifies cumulative kWh, but documented configurations include both device readings and integrated power; the Wh accumulator can join gaps. Therefore call these STORED CUMULATIVE ENERGY FEEDS until actual per-system processing provenance is established. No-interpolation in our client cannot remove unknown upstream interpolation.

Actual interface and cost boundary:
https://heatpumpmonitor.org/api-helper
One request can return a time range and multiple feeds. A full six-hour block's seven hourly cumulative endpoints is an available baseline and must not be excluded.
https://emoncms.org/site/pricing
Hosted feeds cost GBP1/feed/year excluding VAT; this is hosting pricing, not evidence of per-reading API billing. No public historical-query price was established. The online timing benchmark must report request counts, returned bytes, elapsed times and failures without converting them into monetary savings.

Reproducibility and uncertainty boundary:
Raw public metadata and HTTP response hashes are retained in metadata/ and request_log.jsonl. The initial parser overlooked the top-level 'feeds' envelope and requested extra metadata; this was fixed before any time-series values or outcomes were accessed. Selection still follows ascending IDs and original criteria. Public metadata alone does not reveal interior missingness. Training completeness is checked separately under the frozen operational protocol; heldout completeness must not determine source replacement.

External data are not external independent execution, independent human specialist validation, measured production latency, or measured business loss. These require their own evidence.
