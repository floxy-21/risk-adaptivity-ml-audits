VERDICT
No main-source correction is warranted. The paper already connects its
guarantees to an executable acquisition decision. The remaining limitation
is evidence of deployed value under a real restricted-reading contract,
not an omitted algorithm step or code defect that an editorial change
would resolve. Adding another generic practical-benefit paragraph would
repeat existing material. Do not invent a deployment to fill that boundary.

WHAT THE USER OF THE METHOD CAN ACTUALLY DO
Who: an analyst or model-evaluation engineer preparing a comparison from
saved forecasts and incomplete verification records.
When: after a declared evaluation block has ended and its retained counter
endpoints are available, before retrieving optional internal values.
Inputs: forecast contrasts, valid record constraints and endpoints, a
precision requirement, permitted query dictionary, reading/round limits,
and admissibility of bulk access.
Output: a checked acquisition prescription and conditional width guarantee.
On the 222 matched-half shared-query instances, feedback guarantees all
six comparisons reach half-width with two readings. No randomized fixed
two-reading batch can promise more than 50% worst-case success. Thus a
requirement for guaranteed precision changes the protocol choice before
the withheld answers are read. This is an assurance benefit under equal
budgets, not a new forecasting accuracy or downstream model-choice result.

IMPORTANT SCOPE DISTINCTIONS TO PRESERVE
The task-bound protocol wrapper currently supports the29 pairwise
bounded-error tasks. It is not a deployment wrapper for all222 joint
certificates. The main manuscript explicitly says29 external pairwise cases,
while the general joint planner and proof/replay pipeline remain separate.
The wrapper returns a guaranteed width upper bound, not a claim that it has
selected the best model or supplied a complete production reporting system.
New tasks require new verified certificates; unsupported tasks are rejected.
A catalogue exclusion alone is not an impossibility proof.
The actual API supplies bulk access. No observed restricted contract,
measured financial saving, calibrated physical error bound or production
latency reduction is established. The paper already retains these facts.

REVIEW IMPLICATION
Practical value is defensible as an assurance-compatible protocol choice
with inspectable outcomes, particularly the222 exact shared-query cases.
Its operational-economic magnitude remains unmeasured. PeerJ's validity
criteria do not require invented financial impact. The paper should be
judged on the concrete conditional claim it proves and implements, not
on a stronger deployment claim that the data do not support.
No new study or cosmetic practical pitch is required to close this review.
